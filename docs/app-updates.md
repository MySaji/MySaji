# MySaji app update screen

The marketplace root layout now mounts a branded, accessible update gate. It compares the release embedded in the current page against the public, uncached `/api/app-release` endpoint on startup, every minute while visible, and when the app regains focus, visibility or connectivity. When a different release is confirmed, the page becomes inert and an Update & continue dialog is shown. Refreshing loads the latest application without clearing login cookies, push subscriptions, caches or browser storage. Unsaved form entries can be lost; the screen explains this.

The running production build's `.next/BUILD_ID` supplies the release identifier. Preserve this file in deployment packages, including standalone deployments. Development mode, a missing identifier, network errors and malformed responses do not trigger a new block. An update attempt has a 12-second timeout and a retry state. Deploy one consistent build across instances; during rolling deployments different release IDs may otherwise trigger an early update prompt.

Saji Till paths and tenant business websites are excluded. The marketplace's existing service worker remains push-only; it does not cache app pages, so a page refresh is the app-code update mechanism. This does not change or replace Android/Chrome's native installed-app identity/name approval dialog. Browser-managed icon/name updates may still require native confirmation and cannot be forced by JavaScript. The gate detects new web releases, not whether Android has accepted a renamed app. A browser tab or installed app must first have received this implementation before it can detect subsequent releases. No app-store update or reinstall is performed.

Checks: `node --test tests/app-release.test.cjs`; targeted ESLint; a real React browser fixture at 320, 390 and 1280 pixels checks matching/new releases, inert background, initial focus, offline retry and Till exclusion. The fixture uses mocked release responses, not a deployed production release. Release smoke test: open installed MySaji on build A, deploy an approved build B, reopen/focus the app, confirm the required-update screen, tap Update & continue and confirm build B loads. Also test a poor/offline connection and Android's separate native name confirmation.
